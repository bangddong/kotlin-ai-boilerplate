🆕 (2026-11-26) 그래서 일의 중심은 **설계와 AI 산출물 검수**다(E9 · E10). 단 검수 능력은 *직접 짜 본 영역에서만* 선다(E3 · E11 · E12).

그리고 E3 에 따르면 이 능력은 AI 에 통째로 맡기면 **길러지지 않는다.**

## 5. AI 사용 정책 (C7) — 리뷰·판정의 기준

> 🆕 2026-11-26 개정: 중심을 **설계 → 명세 → AI 작성 → 검수**로 옮겼다(§1 결론). 직접 영역은 줄이지 않았다.

| 구분 | 범위 | 누가 쓰나 | 이유 |
|---|---|---|---|
| **설계 (언제나 먼저)** | 경계 · 책임 · 실패 시나리오 · 트레이드오프 — 코드 전에 말이나 짧은 메모로 | 사용자 | 설계를 말하지 못하면 AI 산출물을 판정할 기준이 없다(E2 · E9) |
| **직접** | 테스트(요구사항 정의) · 동시성 제어 · 트랜잭션 경계 · 멱등성 · 장애 진단 | 사용자 | 판단이 들어가고, AI 가 조용히 틀리며(E6), 맡기면 학습이 안 된다(E3). **검수의 밑천**이다(E11) |
| **AI 작성 + 검수** | DTO · 설정 · Swagger · `docker-compose` · k6/스크립트 뼈대 · 문서 서식 · 미션이 따로 허용한 범위 | AI(멘토 세션 포함) → 사용자가 **검수 게이트** 통과 후 수용 | 반복 코드는 맡기고 그 시간을 검수 연습에 쓴다(E10). 받아들인 코드는 내 코드다 |
| **언제나 허용** | 개념 질문 · 공식 문서 찾기 · 생성된 코드의 *설명* 요청 | — | E3 의 고득점 패턴("생성 후 이해" · "개념 질문") |

**검수 게이트** — AI 가 쓴 코드를 받아들이기 전에 사용자가 직접 답한다(멘토가 묻는다).

1. **명세 대조**: 이 코드가 지키는 요구·정책은? 내 테스트가 그걸 잡는가? 돌렸는가?
2. **경계와 실패 경로**: null · 빈 값 · 중복 · 한도 · 예외 · 재시도에서 어떻게 되나?
3. **보이지 않는 결함**: 동시성 · 트랜잭션 · 보안(E5 · E6) — 해당 없으면 "없음"이라고 말한다
4. **설명**: 멘토가 고른 임의의 줄을 설명한다. 못 하면 수용하지 않는다

PR 「AI 사용 기록」에 게이트에서 **찾은 것**(없었으면 "없음")을 함께 적는다.

- PR 본문에 **「AI 사용 기록」**: 무엇을 맡겼나 · 무엇을 고쳤나 · 왜. 안 썼으면 "없음".
- 리뷰 때 멘토가 **임의의 줄**을 골라 설명을 요구한다. 설명 못 한 줄 = 그 줄이 속한 기준 Fail.
- 마일스톤마다 예외를 둘 수 있다(예: M0 = 전부 직접). 미션 문서가 우선한다.

| 🆕 **리뷰 드릴** (C2 · 선택) | 멘토가 `review-drill/m<n>` 에 **결함을 심었다고 알리고** 코드를 둔다(머지 안 함). 결함은 그 마일스톤 주제에서 AI 가 조용히 틀리는 종류(E5 · E6). 사용자는 **AI 없이** 리뷰 → 찾은 것 · 찾은 방법 · 놓친 것. 놓친 결함은 종류별로 `progress.md` 에 쌓아 약점으로 추적한다. AI 초안 검증과 달리 **정답 개수를 알아서** 찾은 비율을 잰다. 🔴 평소 답변에 몰래 섞지 않는다 — 그러면 멘토의 모든 코드를 믿을 수 없게 된다 | M2 · M3 · M5 · M6 (마일스톤당 1회 또는 요청 시) |
| 🆕 **반대 설계** (C8 · C3) | 사용자가 설계를 말하면 멘토가 **가장 강한 대안**을 하나 내놓는다. 사용자는 자기 선택을 수치·실패 시나리오로 방어하거나, 바꾸고 이유를 남긴다. 결정은 PR 본문의 설계 근거로 | 설계 단계마다 (가볍게) |
| 🆕 **뮤테이션 점수** (C1 · 시험 중) | PIT(`./gradlew pitest`)가 코드를 조금씩 망가뜨려 보고 내 테스트가 잡는지 센다. "테스트가 있다"를 넘어 **테스트가 얼마나 단단한가**. 🟡 Kotlin 은 컴파일러 생성 코드 때문에 의미 없는 변이가 섞인다 → 점수 자체보다 **살아남은 변이를 읽는 연습**으로 쓴다. 판정 기준 편입은 M1~M2 에서 써 보고 정한다 | M1 이후 수시 |
