# 시나리오 — AI 크레딧 서비스 요구사항

> 항해 2-1 의 「시나리오 선택」 페이지(e-커머스 · 콘서트) 자리를 대신한다. M1~M7 의 모든 미션은 이 요구사항 위에서 진행한다.
> 원 시나리오와의 대응은 `roadmap.md` 「시나리오」 표.

## 배경

사용자가 **크레딧을 충전**하고, **AI 평가**(예: 이력서·면접 답변 채점)를 요청할 때마다 크레딧이 차감된다.
LLM 은 **느리고**(수 초) · **비싸고**(호출당 과금) · **공급사 호출 한도**(RPM)가 있다 — 이 세 가지가 모든 설계 판단의 출발점이다.

## 기본 요구사항

| # | 기능 | 규칙 |
|:-:|---|---|
| 1 | 크레딧 충전 · 잔액 조회 · 내역 조회 | 최대 잔고 초과 충전 불가. 충전/사용 내역은 시간순 |
| 2 | **AI 평가 요청** | 평가 유형(예: `RESUME`, `ANSWER`)마다 비용이 다르다. 잔액 부족이면 LLM 을 호출하지 않고 실패. 성공 시 결과(점수·피드백)를 저장 |
| 3 | 평가 결과 조회 | 본인 결과만 조회 가능 |
| 4 | **일일 무료 평가 슬롯** | 하루 선착순 30명. 같은 사용자는 하루 1회. 슬롯으로 받은 평가는 크레딧을 차감하지 않는다 |
| 5 | 인기 평가 유형 조회 | 최근 3일간 가장 많이 요청된 평가 유형 상위 5개 |

## 심화 요구사항

| # | 기능 | 규칙 |
|:-:|---|---|
| 6 | **멱등 요청** | 클라이언트가 같은 `Idempotency-Key` 로 두 번 보내면 **LLM 호출·과금은 1회**, 응답은 같다 |
| 7 | **LLM 실패 시 환불** | LLM 호출이 실패(타임아웃·5xx)하면 차감한 크레딧을 되돌린다. 사용자에게 실패 사유를 준다 |
| 8 | 사용량 이벤트 | 평가 1건이 성공할 때마다 사용량(사용자·유형·토큰·비용)을 외부 **과금·분석 플랫폼**에 전달한다. 전달 실패가 평가 성공을 되돌리면 안 된다 |

## 제약

- LLM 은 **포트(인터페이스) 뒤에** 둔다. 테스트·로컬은 **스텁 LLM**(지연·실패를 주입할 수 있어야 한다) — 실키 호출 금지(CLAUDE.md 「보안」).
- 회원가입·로그인은 구현하지 않는다(항해 원문과 같음). 사용자 식별은 `userId` 헤더 또는 경로 변수로 충분하다.
- 인프라는 `docker-compose` 로컬 — 비용 $0.
- 프롬프트 **품질 평가**(M4 고정 평가셋)만 실제 모델을 쓴다 — 로컬 모델(예: Ollama)로, `./gradlew test` 와 분리해서.
